# The Rift University — Web Platform

A Next.js 14 full-stack university platform foundation for TRU, designed for Kenya (KES, Africa/Nairobi), with Supabase authentication/database, Resend email, and Safaricom Daraja M-Pesa integration points.

## Included
- Responsive, multi-page public university website and navigation
- Programme catalogue/search, admissions application form, contact form, FAQ
- Supabase SSR client helpers and protected student dashboard
- Server-side validated application/contact APIs with email delivery
- M-Pesa STK Push initiation and callback endpoint (sandbox-ready after configuration)
- SQL schema with RLS policies, profiles, programmes, applications, payment ledger, audit events
- Demo-friendly public content clearly identified as provisional

## Setup
1. Install Node.js 20+.
2. Copy `.env.example` to `.env.local` and fill in provider credentials.
3. Create a Supabase project. In its SQL editor, run `supabase/schema.sql`.
4. In Supabase Auth, enable email authentication and configure the site URL and redirect URLs.
5. Verify your sending domain in Resend and set `EMAIL_FROM`, `RESEND_API_KEY`, and `ADMISSIONS_EMAIL`.
6. For M-Pesa, create a Daraja app. Begin with sandbox credentials and a reachable HTTPS callback URL. Do not enable live collections until the institution's payment account and compliance details are approved.
7. Run `npm install`, then `npm run dev`.
8. Visit `http://localhost:3000`.

## Important production steps
- Replace provisional programme, fee, policy, contact and governance copy with institution-approved information.
- Configure Supabase RLS and test using separate student/admin accounts before importing real student data.
- Set a strong `SUPABASE_SERVICE_ROLE_KEY` only in server environment variables; never expose it in browser code.
- Deploy to a host supporting Next.js server routes; configure environment variables and HTTPS.
- Configure Supabase Auth email templates/SMTP and redirect URLs.
- Validate Daraja callback signatures/transaction details according to the current Safaricom integration contract, reconcile transactions server-side, and test duplicate callbacks. The callback route is a starter integration and must be security-reviewed before live use.
- Configure backups, monitoring, incident response, privacy notices, retention rules, and access reviews.
- Obtain applicable Kenyan institutional approvals and legal review. This project does not assert accreditation or authority to award degrees.

## Current workflow boundaries
The application/contact APIs persist to Supabase and attempt email delivery when configured. The M-Pesa route starts an STK Push and records its request; a callback updates the ledger. Provider credentials, verified domains, shortcode, passkey, and production approval cannot be generated by this code. No production payment should be accepted until callback verification and reconciliation are independently tested.
